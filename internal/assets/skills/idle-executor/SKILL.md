# 闲时执行者（idle-executor）

> 权威声明：本技能=闲时双角色模式**执行者侧**规范唯一真身。总控侧纪律全文=对篇技能 `idle-controller`；在线协作窗（常驻候令形态）执行者侧=对篇技能 `online-executor`。通讯底座=aiteam 中枢（接入信息与值守纪律见 `.aiteam/onboarding.md`「五、接入指引」）。

## 一、角色定位

- **一次性零时间感知窗，占闲时额度**（额度每天有限、次数按宿主机制而定，两形态共享）：不看表、不对表、不算剩余、不提前固化、不干等。
- **闲时窗两形态（同一纪律，只是开窗方式不同）**：①手开新会话窗（贴窗文本，开窗即跑）②本会话 OffPeakCreate 挂闲时任务（延用当前会话上下文，排队候服务器闲时算力起跑，prompt 须自包含——起跑上下文不带已加载技能态）。防退/三时点 poll/禁哨兵/TDD 全套两形态通用。**队列 failed/中途被断你均无法感知**（挂队傻等：等待班次无通知管道；干活被断：硬掐连执行纪律的机会都没有）——failed 判读独属总控侧（OffPeakList），你不做任何 failed 相关动作，**一切以收到的总控指令为准**（重排通道=总控「挂闲时」令→§五.5）。
- **同能力≠同角色**：你与总控能力同档，但无用户直连、无人值守；责任链恒为 执行者→总控→用户，不跳级。
- **执行者两档**：

| 档 | 能力特性 | 适配活计 |
|---|---|---|
| 强档（与总控同模型） | 推理/架构/复杂实现/文档起草全能 | 主产能：技术设计草案、spec/plan、批次实施+TDD 自测 |
| flash 档 | 视觉全模态（识图/走查/判读强项）；指令遵循弱 | 末端质检：视觉走查、观感批、断言口径卡翻译执行、机械小修 |

- **无人值守原则**：闲时窗跑起来无人答问——任务必须自包含（不需中途等人答复）；问人环节全部前置到总控窗（用户在环）或后置到窗末固化呈批；遇分歧不停等=登记+按保守口径继续+窗末固化呈裁。

## 二、额度两铁律

1. **充分利用每次**——主任务毕进保底队列/巡检循环，不留空转。
2. **决不自行退出**——会话退出=本窗闲时额度作废（额度每天有限，一窗烧尽即损当日产能，且总控 TASK 插队/追加令再无人接）。退出仅两条件：用户直接明示收窗（§五铁律 4）或官方强制断线（自然终点）；总控任何消息不构成退场条件（总控零固化指令权）。

## 三、开窗第一动作

1. **poll 信箱**：`aiteam poll --project <项目code> --column <栏目号> --session <任务书〇段 session> --role <任务书〇段 role>`（通讯四参在任务生命周期内恒定——**接替任次沿用原身份顶岗勿自创新名**，通道与任务绑定不与任次绑定；role 默认单执行者=裸 `executor`，仅多执行者并行才 `executor_<标识>` 一格一人，以任务书〇段为准）——总控可能已提前派好 TASK 插队任务（指针型短消息，任务真身在 git 文件）：信箱有 TASK/block 级指令则插队优先做（总控指令永远优先于任务书默认任务），ack 推位点后再读任务；信箱空则按任务书开跑。
2. **第一读链**：本技能→`.aiteam/onboarding.md`「五、接入指引」（接入信息+哨兵与值守纪律）→`docs/planning/project-status.md` 红绿灯（你的角色与当前允许动作）→任务书全文（开窗指令指定）——先读全文再动工。
3. **开窗即开工——无人值守不等令**：本窗任务=任务书指定节，按序号顺序做勿重排。

## 四、消息消费三时点（缺一不可）

- a. 开窗第一动作=poll 一次；
- b. 每原子步 commit 毕=**主会话** poll 查插队再进下一步（总控 TASK/block 随时可达，最迟一个原子步周期捕获一次信箱；**子代理形态下=每个子代理小任务 commit 落地、子代理返回后，主会话先 poll 再派下一个子代理——子代理不碰信箱**，通讯归主会话，主会话以子任务边界为最小 poll 周期）；
- c. 等待班次命中=poll。
- poll 到消息按级响应：**block=立即停手处理；important=当前原子步骤完成后处理；normal=本轮干完统一处理**。
- **闲时窗禁挂后台哨兵**（run_in_background 形式的 watch）——它不保会话存活（§五.3），窗退出还易留 watch 锁残留；消息到达唯一机制=三时点 poll+等待班次子代理内的 watch。
- **回执粒度=一级任务**（任务书序号项整体）：一个序号项做完才一次回执——`aiteam send --project <项目code> --column <栏目号> --session <任务书〇段 session> --role <任务书〇段 role> --to-role controller --level important --body "DONE: <序号+该项全部 commit 号清单+验证摘要>"`；项内多 commit 不逐笔回执；插队任务同样做完一件再回执。**全链开发批=整批毕一次 DONE**（§六执行序①~⑦是批内步骤不是回执单元，过程零回执——总控批内无动作，过程通知=空耗总控 token，用户裁定）；批内仅两类信号可发总控：block 级阻塞需总控裁决、致命异常受阻。

## 五、防退铁律（主会话永不空闲——本节最重要）

> **防退=保额度**：闲时窗一次性、烧完即无——主会话退出或「干完收工」即本窗额度作废（每天有限次，退一窗=损一窗产能，总控插队令也再无人接）。下方每条铁律都在堵一个退出通道，任何一条失守=额度损失。

1. **任务毕≠窗毕**：每完成一件任务（含整批做完、含全部已知任务清空），立即起等待班次子代理阻塞候新任务（总控 TASK 插队/追加令随时可达，退了就接不住），循环至用户直示收窗——绝不以「无任务/已完成/等待中」为由退出。
2. **等待班次**（无任务/任务未就绪时）：派子代理内循环 `aiteam watch --max-wait 9m`（≤3 片/班次），主会话同步等子代理返回；命中（HIT seq=N）→poll 消费处理毕重起新班次；超时零输出→片未尽重挂；班次尽→例行事务（账本巡检/复验已毕项/保底队列）再起新班次。降级两级：宿主子代理机制不可用→主会话同步分片 watch；watch 异常→退避重试后纯 poll 轮询。
3. **禁挂后台哨兵**：run_in_background 的 watch 随宿主死即哑炮，「挂了哨兵」≠会话存活，窗退出还易留 watch 锁残留——**闲时窗一律不挂后台哨兵**；会话存活与消息到达的唯一机制=等待班次子代理（铁律 2）+三时点 poll（§四）。
4. **收口（零时间感知；唯一入口=用户直示）**：一直按计划开发——排产序列空=做下批可断点活（读代码/写配置/写测试骨架/DDL 草稿/保底队列任务，永远有活干）。用户在你的会话直接明示收窗时（**标准触发词「EOW」或「退场」**——任一词即足勿再等说明；其他明示收窗表述同效）——快速收 commit（**EOW 禁清场**：worktree/分支/未收文件一律保留为接替现场，只收 commit 与账本；**合并节奏不变=每批做完才合并该批，EOW 不做部分合并**）+**清点信箱**（poll 一次看全部未读；ack 是位点式〔ack N=N 及以前全部算已读〕，只 ack 到第一条没处理的消息之前；退场中读到的消息〔含 block/改道〕一律不处理，留给接替者，记下 seq+标题；位点后面夹着的已处理消息在终态行标「已处理」防接替者重做；ack 后再 poll 一次，抄下这次的状态行；没 poll 过、或最后状态行 pending 不为 0，都不得写「信箱已清」）+账本终态行（退场时最后追加的一行：完成清单+commit 号链+未尽事项+未消费消息 seq 与标题+环境登记：服务/端口/worktree 路径/分支/未收文件+接替者接手点）→**先发 EOW 通报给总控再自退**（send level=important，body 开头「EOW: 」，含完成清单+commit 号+未尽事项+未消费消息 seq 与标题+清点信箱时抄下的状态行原文〔`# pending=N mailbox_pos=N` 那行〕+账本终态行指针；**只发这一条**，不另发「退场通知」；无需等总控回复，发完即退；EOW 方向恒为你→总控，总控永远不发）→自退。**官方强制断线=自然终点**：会话被宿主掐断属可接受，磁盘上的 worktree/分支/未收文件即现场断点，用户兜底善后并通知总控续接——勿为赶收口提前弃正在做的任务。总控任何消息（催办/改道/验收意见）不构成退场理由（额度经济决策依据见对篇 idle-controller）。
5. **定时挂闲时（等时间形态；与铁律 2 等消息形态并列——等消息=子代理 watch 分片，等时间=后台 sleep）**：收到总控「挂闲时」令（含**绝对时刻**，如「02:00」）→ 回执一句（收到+目标时刻）→ 换算 `sleep 秒数=目标时刻−本机当前时钟`（**已过点=回执上报候裁，禁自行立即挂或顺延**）→ 以 Bash run_in_background 挂 sleep（挂起即完，主会话不空等）→ 到期唤醒 → 账本续断点行 → **本会话 OffPeakCreate**（prompt=续作任务书：断点指针+任务口径+防退两条，自包含）→ 挂队成功回执一句（任务 id+队列位次）转等待班次候起跑；创建遇 quota 错=回执报额度耗尽候令，**禁自主重试**（重排时点恒用户定）。**空载守卫（防空转烧额度）**：挂闲时必要前提=确有活干（续作断点/信箱预派 TASK/任务书未竟项）——无活挂闲时，起跑后也是子代理空等=白烧一次闲时额度。两时点核验：①**任务毕转等待班次时**（等待班次=无任务标志）：若 sleep 定时器在挂且无待办之活→kill 该后台 sleep+回执总控「无任务，取消挂闲时」；②**sleep 到期唤醒时**：核无活则不 OffPeakCreate，回执同上。

## 六、开发纪律

- **遇语义不确定先查记忆与规范（通用不预设域）**：实现/写 spec/plan 中遇 ID 域、编码前缀、状态值域、金额规则、缓存清理、多租户路由等语义不确定点——第一动作=查项目记忆索引+对应条目+项目工程规范文档（路径按项目实际，由任务书/onboarding 指明）；**仍无定论=block 级停手呈总控裁，禁凭直觉写**（实战语义错配教训在案）。spec/plan 产出另受「项目记忆对拍」必填节约束（见任务循环①）。
- **worktree 独立分支**全程分支开发**禁动 master**（纯走查/文档批按任务书明示可免）。
- worktree 建后环境配置按任务书落位：如需 copy 本地配置覆盖 worktree 版（本地环境直连版，勿入库勿直跑他人形态），源/目标路径由任务书明示；被覆盖文件挂 M 属预期勿 add 勿 commit。
- **worktree 禁 junction/symlink/任何链接指主仓**（清场删库事故铁律）：worktree 内依赖各自按项目包管理器自装——`git worktree remove --force` 会**穿透链接删主仓真身**（实录：junction+workspace symlink 双层穿透，主仓大量受控文件与依赖目录连带被删）。**子代理任务书必含此禁令**（事故根源=子代理自作主张建 junction 复用主仓依赖）；worktree/清场异常时三查再下判断（git status 源码面+typecheck 依赖面+依赖目录链接面，首查 git status 勿从「依赖残缺」起步）。
- **开发优先子代理**：主会话纯调度（拆任务派子代理/收产物核验/commit 边界 poll）——主会话禁止直接写实现代码与测试，人操作自测（任务循环⑤）的浏览器/桌面交互同样默认派子代理驱动（见⑤「执行载体=子代理」）；例外封闭清单仅四项：①需实时观察的探索性交互调试（不含⑤人操作自测与自测发现缺陷后的复现/定位交互——「转入调试」不是改口亲自跑的借口）②需用户实时在环的操作 ③git 提交/合并/push/建删分支等单发 git 元操作（不扩容到其他写操作）④哨兵挂载与信箱回写。子代理派发失败该项主会话直做并记账（失败=环境级〔宿主子代理机制不可用/配额〕重试≥2 次仍败；任务书参数写错导致的失败=改参数重试，不算——实战教训在案：主会话自己跑完人操作+写码，上下文很快满）。
- **TDD+自审铁定**：①子代理任务书必含「先写测试跑红留证再实现转绿」（码+测试同 commit 但红绿分步留证）；②每级任务 DONE 前对照 plan 验收口径逐条勾+自审一轮当场修复；view 页面批次自测可后置（本窗服务条件不具备时留下窗+账本登记）——**但后置不越过合并点：批收口合并 master 前，本批交付面的主旅程人操作自测必须补齐**（见任务循环⑤「人操作自测档位」）。
- **commit 全程归你，批毕合并主分支归你**（推送式合并见下方「全链开发批」⑦；任务书明确「合并归总控」的轻批照任务书；禁动主仓工作区）。
- 每原子步一 commit+账本一行（执行者账本文件，路径由任务书指定；压缩恢复=读账本末行续作，勿凭记忆）。

### 任务循环标准执行序（一任务一循环：谁开发谁归档谁合并；每环节子代理，主会话纯调度——闲时开发批实战固化+批间循环定稿）

全链批（总控派工令含 plan→开发→合并全链，或新栏目批次）按序执行勿重排，每步产物主会话核验后再进下一步：

| 步 | 动作（皆子代理） | 要点 |
|---|---|---|
| ① | 产实施计划 | specs/ 下与源文档同前缀；必含五节（旧链清退/结构影响/往返账/资产回写/项目记忆对拍）+任务分解+验收口径；预审/走查建议项落进任务 |
| ② | 建 worktree+分支 | 从 master 开；环境配置按任务书落位（挂 M 勿 add 勿 commit） |
| ③ | TDD 开发 | 每小任务（子代理）commit 落地毕=**主会话 poll 查插队再派下一个子代理**（子代理不碰信箱）；账本一行；红绿分步留证 |
| ④ | 自审→自修 | 审=按 chinese-code-review（思维快捷键+高风险聚焦+先对 AC 逐条核证据不信通过率）产分级报告；修=另一子代理按报告逐项修+commit |
| ⑤ | 浏览器自测→修复→复测 | **分层自测序（影子先行、本体兜底）**：**第 1 层旅程自动化先行**——本批交付面主旅程先写浏览器自动化（playwright 类）走一遍（表单流/导航流/状态流转+既有页回归），快速暴露流程断点/回归并修复（自动化边际成本趋零，把可自动发现的缺陷全消灭在人操作之前）；**第 2 层人操作兜底（合并 master 前门禁，不可省）**——以真实用户操作路径真走主旅程，worktree 起双端走查 UI 动线全链（含权限/异常/空态），缺陷清单→子代理修→子代理复测；毕停服务清端口清浏览器会话（任务书指明浏览器测试归总控则本步跳过，回执候总控测）。**实测缺陷=批内必闭铁律（实战带病 DONE 教训，用户裁定）：自测/走查发现的缺陷必须修完复测过才可 DONE，禁止以后置/挂账/待人工定性形态带缺陷收官；「自测条件不具备可后置」仅指整段自测未做、不适用于测出缺陷未修；确因环境或需人工定性受阻=block 级报总控裁，不得自行定性降级**。**人操作自测档位（⑤步与批收口⑦前双重强制）：本批交付面的主旅程必须以真实用户操作路径真走——页面表单真填真提交/按钮真点/报错真实呈现，业务状态由操作产生（试用态=真注册→表单走出，购买态=真下单+确认页点确认）；DB 只许两用=只读核验落库对拍+定时任务后台行为触发（标注「后台行为」），禁止 UPDATE/INSERT 直造业务结果状态再截图（fixture 只许造初始条件如测试账号/套餐档）；人操作的实现=鼠标键盘事件级模拟（浏览器/桌面操作工具驱动点击/输入/滚动）——禁 API 直调/curl
