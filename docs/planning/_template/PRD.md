## 2. 功能需求清单（FR）

> 命令/接口名约定：{{NAMING_CONVENTION}}；参数细节归 S3。
> **AC 可脚本化判据写法要领**（本模板核心纪律，参考样例 72 AC 全部按此写）：
> 1. 每条 AC 必须能写成可执行脚本或可机械核验的检查项，跑得出 PASS/FAIL——判据优先用：退出码/HTTP 状态码、输出含某要素、计数相等（如并发 N 条=入库 N 条）、时延上限（如响应 <5s）、结构断言（如表/字段存在）；
> 2. 禁「体验良好」「运行稳定」类不可判据表述；确属人工走查的（如页面无某控件）写成走查+接口清单双重核验；
> 3. 正常/边界/失败三态各覆盖：成功行为、重复与幂等、目标不存在与冲突拒绝、服务不可达显式报错；
> 4. 一条 AC 只验一件事；跨条共用的判据互相引用编号不重抄。
