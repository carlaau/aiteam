- **共享总线**：团队经共享远端仓（自建 bare 仓或托管平台）协作，每位执行者独立 clone 到各自机器开发；分支按批次/任务命名，个人远端分支与本地分支同名对应。
- **push 频率**：每任务收口（测试绿+静态检查过）即 push 一次 WIP 进度到个人远端分支，防本机故障丢提交；跨任务囤积本地提交不 push 禁止。
- **fetch 前置自查**：开工前与 push 前先 `git fetch`，对照远端确认无他人新提交；分叉先解决再继续，禁 `--force` 覆盖他人提交（误覆盖的修复代价远高于 fetch 一次）。
- **合并三步**：自测过后，①`git fetch` 后 `git rebase master` 到最新（rebase 冲突由合并者解决，解决后全量重跑验证，仍冲突则循环「解决→重跑」直至全绿，跳过验证禁止）→ ②全量重跑（全部测试+静态检查零报错）→ ③`git merge --no-ff` 回 master 并 push 更新远端主干。
- **合并序**：多人并行合并按任务档既定行序串行，见自己行以上全部「已合并」才走合并三步；git 写全局串行由行序制保证，不靠约定靠状态面。
