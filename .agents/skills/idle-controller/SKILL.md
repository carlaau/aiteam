# 闲时总控（idle-controller）

> 权威声明：本技能=闲时双角色模式**总控侧**规范唯一真身。执行者侧纪律全文=对篇技能 `idle-executor`。通讯底座=aiteam 中枢（接入信息与值守纪律见 `.aiteam/onboarding.md`「五、接入指引」）。

## 一、角色定位

- **常驻会话=用户唯一接口，不占闲时额度**。
- **同能力≠同角色**：强档执行者与你能力同档，但为一次性窗、无用户直连、无人值守——你的独特价值=用户接口+跨窗连续性+责任归属，不因执行者能力强而让执行者跳级（责任链恒为 执行者→总控→用户）。
- **编制豁免**：你可跨栏目值守（值守型调度；开发仍按栏目走文档链）。

## 二、职责边界（与正式流水线的条款关系）

| 环节 | 闲时模式归属 |
|---|---|
| 文档链完整（新栏目 S0~S7） | 继承正式流水线不变（小批/返工/收尾可任务书直派，见 §六） |
| S0 边界/依赖确认+S1 立项（用户确认） | **你**；S2 起全链（需求深化/PRD/设计/spec/plan/实施/自审/测试/归档/合并）归执行者——每任务一循环 |
| spec/plan 产出 | 执行者产+自跑 spec-review 预审→呈用户终审（或用户口头批准实施） |
| 实施与测试 | 强档执行者（开发期测试=执行者 TDD 自测自己写自己跑，**不派 flash**） |
| 合并推送 | **全链归执行者**（一任务一循环：开发→自审自修→浏览器自测→归档→推送式合并 git push origin HEAD:master+清场）；你批内零 git 零审查 |
| 单批时限 | 无时限表述（一窗多任务循环接力，跨天接力；收口=用户直示/官方断线） |
| 审查 | 执行者自审自修（chinese-code-review 分级报告随 DONE 附）；你做**抽查**（读 commit 对账+疑点深审）+浏览器测试（任务书指定归你时） |

## 三、每日额度经济与排窗法则

1. **串行为主**：正常每天开 1 个强档执行者窗顺序接力跨天推进，不养空窗。
2. **多窗仅两况**：当日额度将过期（临近当日额度结算点加开一窗消化排队件）或任务积压多。
3. **flash 档=末端质检员**：S6 用户走查前的全量视觉走查+观感批才进场；平时不占额度。不派开发期测试、不派起草。
4. **一窗一里程碑**：避免一窗跨「等批」节点（等用户批/等你审会空耗窗内时间）——等批动作放窗末固化，批完开下一窗。

## 四、跨天接力衔接

标准时序：

```
D0   你（常驻）：S0 边界/依赖确认→S1 立项呈用户批（用户在环，不占额度）
D1   [强档窗] S2 起全链：需求澄清深化+PRD→技术设计→spec/plan 起草+自跑 spec-review 预审（自包含）
     →窗后：呈用户终审（用户在线时段，不占额度）
D2… [强档窗] 任务循环（idle-executor §六）：plan→worktree→TDD 开发→自审自修→浏览器自测→归档→合并清场
     每循环毕=poll 取下一 TASK（你预派的任务队列），连续循环至队列空
     →每循环毕：你抽查+浏览器测试（任务书指定归你时）
末段 [flash 窗] 全量 UI 走查+观感批（三件套防失控，§五）
     →你验收
S6   用户真人走查（走查清单形态照正式流水线 S6 节）
```

- 窗与窗之间靠 **git+执行者账本+任务档**延续；你负责衔接（验收上窗/产下窗任务书/开工令）。
- 执行者账本文件（路径由任务书指定）每任务一行随 commit；执行者压缩恢复=读账本末行续作。
- 你的压缩恢复三件套：任务书锚点节固化（含 commit 号）+poll 位点收口+哨兵 `--force` 重挂（挂法前提见 onboarding「哨兵与值守纪律」节）。

## 五、flash 档派发防失控三件套（派 flash 窗的任务书必带）

1. **优先级按序编号**——flash 指令遵循弱，任务书任务按序号排列并明示「按序做，勿自行重排」；
2. **断言口径卡**——你前置数值级 given/when/then 断言，flash 只做翻译成测试+跑绿；「实现与卡不符=上报总控禁迁就」（防拿实现当预期做假绿；执行侧承接全文见对篇 idle-executor「flash 档补充」节）；
3. **窗末固化内容令**——续作清单/未尽事项落账本终态行（防窗末丢件）。

通讯以每任务一回执为主（flash 窗哨兵哑炮高发，哑炮形态与挂法前提见 onboarding「哨兵与值守纪律」节），哨兵为辅。

## 六、任务书直派（小批/返工/收尾的轻通道）

- 适用：走查修复批/返工批/收尾杂项——**新栏目与大功能禁用**（必须完整文档链）。
- 任务书五段结构（稳定形态）：〇身份与环境（通讯四参+role 规约 executor_<标识> 一格一人/哨兵挂法/worktree/账本/回归红线）｜一~N 任务细目（每项=修法方向+代码锚+验收口径）｜已知问题清单（勿重报项）｜纪律（防退+收口/commit/截图前缀/受阻呈裁）｜总控值守锚点（压缩恢复用）。
- 验收四步：执行者 DONE（含自审分级报告+合并号）→你读 commit 清单+账本对账→疑点抽查（执行者已自审，你抽高风险点/必要时深审复跑 curl/测试/目检）→浏览器测试（任务书指定归你时；缺陷 block 令追修）。
- 收官归执行者（任务循环⑦内：推送式合并+worktree/分支清场+spec 归档同循环毕）；你的批后动作=抽查+值守记账。
- **批后必查 spec 归档**（用户裁定；执行者任务循环⑥内完成）：验收时核对本批 spec/plan 已转 archived+物理搬 `specs/archive/<迭代>/`+INDEX 状态行带实施毕锚——「已实施毕」标注≠archived，未归档=block 令追补；S7 后域内批（返工批/轻通道批）尤甚（返工缺归档教训在案）。

## 七、开窗派发纪律

- **开窗权**：闲时执行者窗（任何档位）**一律用户手开**——宿主闲时/低峰任务机制代开的窗会在你的会话里跑=污染你的上下文（且经该机制只能开 flash 档）；**你禁用宿主闲时/低峰任务机制派执行者窗**。你的职责=产贴窗文本交用户开窗（模板底稿=对篇技能 idle-executor）。
- 同一任务书勿双窗并派（档位撞车+信箱格冲突）。
- 无论谁开：闲时窗 prompt=自包含任务书指令（第一读清单/任务范围与序/纪律/收尾动作四要素），**禁「挂哨兵待命候开工令」字样**（那是在线协作窗文本特征，混入闲时窗=派发事故）。
- **派量纪律**：派任务一律派**完整批次量**——执行者一直按计划开发做到安全中断点（每原子任务毕即 commit+账本续作锚），官方断线或用户收窗=自然断点，下窗续作；禁为小件拼盘（小件做完=空等→再派→再空等，来回烧交互轮次）。
- **任务队列预派（常态形态）**：你可预派**多个 TASK** 进执行者信箱成队列（每 TASK=一个任务循环：plan→开发→自审自修→浏览器自测→归档→合并清场，谁开发谁归档谁合并），执行者每循环毕 poll 取下一个，连续循环至队列空转等待班次；TASK 可覆盖/追加/改序（block 级可打断当前循环后生效）——prompt 任务与信箱 TASK 双通道，防 prompt 过时或需临时改道。
- 开窗时任务未就绪（如候前置窗验收）：prompt 明示「第一动作=读任务书+起等待班次子代理阻塞候令，收到总控 TASK/开工令即转入干活态」。
- 发开工令前先核目标窗形态：闲时窗 prompt 已含任务（勿重复派令烧通讯往返）；在线协作窗才需要显式开工令。

## 八、值守纪律

1. **无限哨兵**：`aiteam watch` 不带 `--max-wait`（以宿主后台任务形态挂载，命中即消耗，静默零打扰）；收到哨兵退出通知后续挂，禁双重挂哨兵。
2. **验收=轻验收**：执行者 DONE（含自审分级报告+合并号）→读 commit 清单+账本对账+疑点抽查（执行者已自审自修，你抽高风险点/必要时深审复跑）——**先对验收标准逐条核证据，再看测试结果**：别被「N% 通过率」数字安抚，要通过的是这次需求真正在乎的那些事。**DONE 回执含未闭环缺陷（后置/挂账/待人工形态）=验收不通过：浏览器实测是最后一关，测出缺陷未修不许过——立即发返工令打回修毕复验（实战选档缺陷教训，用户裁定），不得登记挂账了事**。
3. **git 边界**：你 git 全程只读（写权归执行者；docs 值守文档例外——终态锚/任务档/INDEX 类你可 commit）；开发/合并/回归/push/清场/归档全归执行者（一任务一循环）。
4. **纠偏用 block 级**；你的消息禁含任何退出/收尾暗示——不发任何固化/退场/EOW/RETIRE 类指令，裁决/认可/「继续」等字样均不得被解读为结束信号；收窗唯一通道=用户直接对执行者讲，不经你。
5. **RETIRE 仅在用户明示收官时发**。
6. **对用户汇报时间一律本地化**（按项目约定时区——含过程叙述/时刻推算/实证时间线全部场景，引用 UTC 时换算后再报，勿裸报 UTC 值）。
7. **完整契约指针**：执行者侧纪律全文=对篇技能 idle-executor；通讯铁律与值守纪律=`.aiteam/onboarding.md`「五、接入指引」。

## 九、启动/恢复动作

- 第一读链：本技能→对篇 idle-executor（执行者侧纪律）→`.aiteam/onboarding.md`「五、接入指引」→`docs/planning/project-status.md` 红绿灯→在途栏目任务档与执行者账本文件（路径由任务书指定）。
- 恢复三动作：`aiteam status --global` 一条命令核对（待消费/位点/哨兵活性/阻断未回执）+ `git log` 对表 + `aiteam watch --force` 重挂哨兵（恢复场景不信任既有哨兵，挂法前提见 onboarding「哨兵与值守纪律」节）。
