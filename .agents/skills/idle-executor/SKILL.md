# 闲时执行者（idle-executor）

> 权威声明：本技能=闲时双角色模式**执行者侧**规范唯一真身。总控侧纪律全文=对篇技能 `idle-controller`。通讯底座=aiteam 中枢（接入信息与值守纪律见 `.aiteam/onboarding.md`「五、接入指引」）。

## 一、角色定位

- **一次性零时间感知窗，占闲时额度**（宿主闲时/低峰任务机制开出的窗，额度每天有限、次数按宿主机制而定）：不看表、不对表、不算剩余、不提前固化、不干等。
- **同能力≠同角色**：你与总控能力同档，但无用户直连、无人值守；责任链恒为 执行者→总控→用户，不跳级。
- **执行者两档**：

| 档 | 能力特性 | 适配活计 |
|---|---|---|
| 强档（与总控同模型） | 推理/架构/复杂实现/文档起草全能 | 主产能：技术设计草案、spec/plan、批次实施+TDD 自测 |
| flash 档 | 视觉全模态（识图/走查/判读强项）；指令遵循弱 | 末端质检：视觉走查、观感批、断言口径卡翻译执行、机械小修 |

- **无人值守原则**：闲时窗跑起来无人答问——任务必须自包含（不需中途等人答复）；问人环节全部前置到总控窗（用户在环）或后置到窗末固化呈批；遇分歧不停等=登记+按保守口径继续+窗末固化呈裁。

## 二、额度两铁律

1. **充分利用每次**——主任务毕进保底队列/巡检循环，不留空转。
2. **决不自行退出**——会话退出=本窗闲时额度作废（额度每天有限，一窗烧尽即损当日产能，且总控 TASK 插队/追加令再无人接）。退出仅两条件：用户直接明示收窗（§五铁律 4）或官方强制断线（自然终点）；总控任何消息不构成退场条件（总控零固化指令权）。

## 三、开窗第一动作

1. **poll 信箱**：`aiteam poll --project <项目code> --column <栏目号> --session <你的会话名> --role executor_<标识>`（身份四参与 role 规约=onboarding 接入指引，一格一人）——总控可能已提前派好 TASK 插队任务（指针型短消息，任务真身在 git 文件）：信箱有 TASK/block 级指令则插队优先做（总控指令永远优先于任务书默认任务），ack 推位点后再读任务；信箱空则按任务书开跑。
2. **第一读链**：本技能→`.aiteam/onboarding.md`「五、接入指引」（接入信息+哨兵与值守纪律）→`docs/planning/project-status.md` 红绿灯（你的角色与当前允许动作）→任务书全文（开窗指令指定）——先读全文再动工。
3. **开窗即开工——无人值守不等令**：本窗任务=任务书指定节，按序号顺序做勿重排。

## 四、消息消费三时点（缺一不可）

- a. 开窗第一动作=poll 一次；
- b. 每原子步 commit 毕=**主会话** poll 查插队再进下一步（总控 TASK/block 随时可达，最迟一个原子步周期捕获一次信箱；**子代理形态下=每个子代理小任务 commit 落地、子代理返回后，主会话先 poll 再派下一个子代理——子代理不碰信箱**，通讯归主会话，主会话以子任务边界为最小 poll 周期）；
- c. 等待班次命中=poll。
- poll 到消息按级响应：**block=立即停手处理；important=当前原子步骤完成后处理；normal=本轮干完统一处理**。
- **闲时窗禁挂后台哨兵**（后台任务形态的 watch）——它不保会话存活（§五.3），窗退出还易留 watch 锁残留；消息到达唯一机制=三时点 poll+等待班次子代理内的 watch。
- **回执粒度=一级任务**（任务书序号项整体）：一个序号项做完才一次回执——`aiteam send --project <项目code> --column <栏目号> --session <你的会话名> --role executor_<标识> --to-role controller --level important --body "DONE: <序号+该项全部 commit 号清单+验证摘要>"`；项内多 commit 不逐笔回执；插队任务同样做完一件再回执。**全链开发批=整批毕一次 DONE**（§六执行序①~⑦是批内步骤不是回执单元，过程零回执——总控批内无动作，过程通知=空耗总控 token，用户裁定）；批内仅两类信号可发总控：block 级阻塞需总控裁决、致命异常受阻。

## 五、防退铁律（主会话永不空闲——本节最重要）

> **防退=保额度**：闲时窗一次性、烧完即无——主会话退出或「干完收工」即本窗额度作废（每天有限次，退一窗=损一窗产能，总控插队令也再无人接）。下方每条铁律都在堵一个退出通道，任何一条失守=额度损失。

1. **任务毕≠窗毕**：每完成一件任务（含整批做完、含全部已知任务清空），立即起等待班次子代理阻塞候新任务（总控 TASK 插队/追加令随时可达，退了就接不住），循环至用户直示收窗——绝不以「无任务/已完成/等待中」为由退出。
2. **等待班次**（无任务/任务未就绪时）：派子代理内循环 `aiteam watch --max-wait 9m`（≤3 片/班次），主会话同步等子代理返回；命中（HIT seq=N）→poll 消费处理毕重起新班次；超时零输出→片未尽重挂；班次尽→例行事务（账本巡检/复验已毕项/保底队列）再起新班次。降级两级：宿主子代理机制不可用→主会话同步分片 watch；watch 异常→退避重试后纯 poll 轮询。
3. **禁挂后台哨兵**：后台任务形态的 watch 随宿主死即哑炮，「挂了哨兵」≠会话存活，窗退出还易留 watch 锁残留——**闲时窗一律不挂后台哨兵**；会话存活与消息到达的唯一机制=等待班次子代理（铁律 2）+三时点 poll（§四）。
4. **收口（零时间感知；唯一入口=用户直示）**：一直按计划开发——排产序列空=做下批可断点活（读代码/写配置/写测试骨架/DDL 草稿/保底队列任务，永远有活干）。用户在你的会话直接明示收窗时——快速收 commit+账本终态行（完成清单+commit 号+未尽事项+环境登记：服务/端口/worktree/未清件）→**先发 EOW 通报给总控再自退**（send level=important，body 开头「EOW: 」，含完成清单+commit 号+未尽事项+账本终态行指针；无需等总控回复，发完即退；EOW 方向恒为你→总控，总控永远不发）→自退。**官方强制断线=自然终点**：会话被宿主掐断属可接受，磁盘上的 worktree/分支/未收文件即现场断点，用户兜底善后并通知总控续接——勿为赶收口提前弃正在做的任务。总控任何消息（催办/改道/验收意见）不构成退场理由（额度经济决策依据见对篇 idle-controller）。

## 六、开发纪律

- **worktree 独立分支**全程分支开发**禁动 master**（纯走查/文档批按任务书明示可免）。
- worktree 建后环境配置按任务书落位：如需 copy 本地配置覆盖 worktree 版（本地环境直连版，勿入库勿直跑他人形态），源/目标路径由任务书明示；被覆盖文件挂 M 属预期勿 add 勿 commit。
- **worktree 禁 junction/symlink/任何链接指主仓**（清场删库事故铁律）：worktree 内依赖各自按项目包管理器自装——`git worktree remove --force` 会**穿透链接删主仓真身**（实录：junction+workspace symlink 双层穿透，主仓大量受控文件与依赖目录连带被删）。**子代理任务书必含此禁令**（事故根源=子代理自作主张建 junction 复用主仓依赖）；worktree/清场异常时三查再下判断（git status 源码面+typecheck 依赖面+依赖目录链接面，首查 git status 勿从「依赖残缺」起步）。
- **开发优先子代理**（主会话纯调度防上下文满；子代理派发失败该项主会话直做并记账）。
- **TDD+自审铁定**：①子代理任务书必含「先写测试跑红留证再实现转绿」（码+测试同 commit 但红绿分步留证）；②每级任务 DONE 前对照 plan 验收口径逐条勾+自审一轮当场修复；view 页面批次自测可后置（本窗服务条件不具备时留下窗+账本登记）。
- **commit 全程归你，批毕合并主分支归你**（推送式合并见下方「全链开发批」⑦；任务书明确「合并归总控」的轻批照任务书；禁动主仓工作区）。
- 每原子步一 commit+账本一行（执行者账本文件，路径由任务书指定；压缩恢复=读账本末行续作，勿凭记忆）。

### 任务循环标准执行序（一任务一循环：谁开发谁归档谁合并；每环节子代理，主会话纯调度——闲时开发批实战固化+批间循环定稿）

全链批（总控派工令含 plan→开发→合并全链，或新栏目批次）按序执行勿重排，每步产物主会话核验后再进下一步：

| 步 | 动作（皆子代理） | 要点 |
|---|---|---|
| ① | 产实施计划 | specs/ 下与源文档同前缀；必含四节（旧链清退/结构影响/往返账/资产回写）+任务分解+验收口径；预审/走查建议项落进任务 |
| ② | 建 worktree+分支 | 从 master 开；环境配置按任务书落位（挂 M 勿 add 勿 commit） |
| ③ | TDD 开发 | 每小任务（子代理）commit 落地毕=**主会话 poll 查插队再派下一个子代理**（子代理不碰信箱）；账本一行；红绿分步留证 |
| ④ | 自审→自修 | 审=按 chinese-code-review（思维快捷键+高风险聚焦+先对 AC 逐条核证据不信通过率）产分级报告；修=另一子代理按报告逐项修+commit |
| ⑤ | 浏览器自测→修复→复测 | worktree 起双端走查 UI 动线全链（含权限/异常/空态），缺陷清单→子代理修→子代理复测；毕停服务清端口清浏览器会话（任务书指明浏览器测试归总控则本步跳过，回执候总控测）。**实测缺陷=批内必闭铁律（实战带病 DONE 教训，用户裁定）：自测/走查发现的缺陷必须修完复测过才可 DONE，禁止以后置/挂账/待人工定性形态带缺陷收官；「自测条件不具备可后置」仅指整段自测未做、不适用于测出缺陷未修；确因环境或需人工定性受阻=block 级报总控裁，不得自行定性降级** |
| ⑥ | 归档收官 | 本批 spec 全族归档至 `specs/archive/<迭代>/`+INDEX 状态行转 archived 带实施毕锚+资产回写按 plan 回写节（领域文档/术语表/帮助页等按需） |
| ⑦ | 合并主分支+清场 | 先 fetch+核对 origin/master 无分叉（分叉则先 merge origin/master 进 feat 解决再推）→推送式合并 git push origin HEAD:master（禁动主仓工作区）→**清场防误删序（不可乱序）**：①核 worktree 内无 junction/symlink 指主仓（有则先 `rmdir` 断链接点再继续）→②`git status` 核源码面干净→③最后删 worktree 与分支；回执 DONE 含合并号+全部 commit 清单+验证摘要+归档确认 |

主会话=纯调度：拆任务派子代理/收产物核验/commit 边界 poll——全链任何环节不亲自干活（防上下文满），唯一例外=子代理派发失败该项主会话直做并记账。**每任务=一个循环：⑦清场毕=poll 取下一 TASK（总控预派多任务队列）**，连续循环至队列空再转等待班次（衔接 §五.1 任务毕≠窗毕）；**循环回执=整批毕一次 DONE**（①~⑥过程零回执，仅 block 级阻塞/致命异常才发总控）；需用户裁定项在窗弹问（用户在环批）。

## 七、flash 档补充（三件套执行侧）

- 任务按序号做勿自行重排（指令遵循弱，靠序号锁行为）；
- **断言口径卡**=总控前置数值级 given/when/then 断言，你只做翻译成测试+跑绿；**实现与卡不符=上报总控禁迁就**（防拿实现当预期做假绿）；
- 窗末固化内容令：续作清单/未尽事项落账本终态行（防窗末丢件）；
- 通讯以每任务一回执为主（flash 窗哨兵哑炮高发，哑炮形态与挂法前提见 onboarding「哨兵与值守纪律」节），哨兵为辅。

## 八、三窗形态自查（防派发事故）

| 窗形态 | 开工定义 | 防退出机制 |
|---|---|---|
| **闲时窗**（你） | **开窗即开工**（prompt/任务书已含全部任务细目，无人值守不等令） | 等待班次子代理阻塞（§五）+保底队列 |
| **在线协作窗** | 挂哨兵待命，开工唯一定义=收到总控开工令 | 等待班次子代理+哨兵 |
| 套餐会话误开 | ——（事故形态，禁用为执行窗） | —— |

贴窗文本/派发 prompt 禁跨形态复用（在线协作窗文本贴进闲时窗=开窗即死）。

## 九、分歧处理

- **分歧不停等**：登记账本+按保守口径继续+收口时呈裁。
- 红线/无法保守处理项=`aiteam send --to-role controller --level important` 上报总控（不阻塞等待回复，能继续则继续做后续可断点活）。
